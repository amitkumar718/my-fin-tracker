# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Build

Builds run on the user's Android device via Termux, not on the dev machine. There is **no Gradle** — `build-local.sh` orchestrates `aapt2`, `javac`, `d8`, and `apksigner` directly.

Do **not** run `sh build-local.sh` yourself. The user runs builds. If a build is explicitly requested, trigger it through the Termux bridge:

```
bash /root/tx.sh "cd /data/data/com.termux/files/home/android-apps/my-fin-tracker && sh build-local.sh 2>&1"
```

First confirm the bridge is running: `pgrep -f termux_bridge`. If it's not, ask the user to start it.

Output APK: `build/local/myfintracker-debug.apk`. Install with `adb install -r …` and grant SMS: `adb shell pm grant com.ldsa.myfintracker android.permission.READ_SMS`.

## Toolchain constraints (D8 / Termux)

The device-side `d8` is older and strict. When writing Java:

- Use **static** inner classes, not anonymous inner classes.
- No lambdas or method references.
- `Adapter.getItem` must return `Object` (not a parameterized type), to match the erased signature `d8` expects.
- Java source/target is **8**; min API 21, target API 34.

`app/src/main/java/com/ldsa/myfintracker/R.java` is auto-generated by `aapt2 link` during the build. Do not hand-edit it — edit the XML in `app/src/main/res/` instead.

## Architecture

Single-module Android app, package `com.ldsa.myfintracker`. Source layout:

- `db/` — `ExpenseDatabase` extends `SQLiteOpenHelper`. Entities: `Expense`, `Trip`, `Card`, `SenderConfig`, `ExtractionPattern`, `PdfStatement`. **Schema evolution rule: never drop tables.** `onUpgrade` uses `CREATE TABLE IF NOT EXISTS` and `ALTER TABLE ADD COLUMN` so user data persists across installs. Bump `DB_VERSION` and add an upgrade branch when changing schema.
- `sms/` — `SmsReader` queries the system SMS content provider; `SmsMessage` is the row model.
- `pdf/` — `PdfTextExtractor` is a hand-rolled PDF text-layer extractor (FlateDecode only, position-aware via `Tm`/`Td`/`TD`/`T*`, with heuristic multi-line table-row merging). `PdfDecryptor` handles Standard Security Handler R2/R3/R4 (128-bit AES max). See `limitations.md` for the exact bounds — R5/R6, 256-bit AES, scanned PDFs, LZW/CCITT/JBIG2 streams, and non-Latin ToUnicode CMaps are **not** supported, by design.
- `ui/` — Activities and `RecyclerView` adapters. Entry point is `MainActivity`; the landing screen is user-configurable via SharedPreferences file `fin_prefs`, key `landing_page` (expenses vs SMS inbox). All non-launcher activities are `exported="false"`.

### Data-flow pattern

Expenses can be created three ways: manual (`AddExpenseActivity`), from a single SMS (`SmsMapActivity` runs per-sender extraction regexes stored in `ExtractionPattern` rows), or by bulk-importing a bank PDF statement (`PdfInboxActivity` → `StatementImportActivity`, extraction templates stored per-sender in the `pdf_field_pat` table). Trips group expenses for travel reporting.

## Known limitations

See `limitations.md` for the PDF extractor's documented failure modes (3+ wrapping columns, encrypted-PDF revisions, scanned PDFs, exotic compression filters). Prefer updating that file over inlining caveats in code comments.
